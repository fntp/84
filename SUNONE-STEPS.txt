---- 现在卡在哪 -----------------------------------------------------

症状：准星对着人头时，一会儿往左上跳、一会儿往右上跳，跳得非常快；
倍率压到 0.05 只是把跳的幅度压小了，跳的频率一点没变。

原因（读了源码，不是猜的）：

   这个工具每帧都会拿"上一帧到这一帧目标挪了多少"往前外推一段，
   外推的时间 = predictionInterval + 检测延迟补偿 + 额外预测。

   卡尔曼关掉之后，"挪了多少"就不再是滤波后的速度，而是
   **两帧检测框之间的原始抖动**；而画面那一帧到鼠标真正动之间隔着
   20~50ms，于是每帧都拿这个抖动往前推 20~50ms 的位置。
   下一帧抖动反号，目标点就跳到另一边 —— 表现出来就是"很快地左右来回跳"。
   跳多远由倍率决定，跳的频率是帧率决定的，所以降倍率只会让幅度变小。

要做的是把外推时间彻底变成 0。就差最后这一处：
kalman_compensate_detection_delay（检测延迟补偿），默认是 true。
它一关，lookahead 就是 0，predict() 直接返回当前位置，跳就没了。

   （源码位置，供核对：
     include/aim_kalman.h   predict()  —— lookahead <= 0 时直接 return position()
     mouse/mouse.cpp        currentPredictionLookaheadSec() —— 把检测延迟加进 lookahead
                            currentDetectionDelaySec()      —— 检测延迟 = 这一帧的年龄
     mouse/mouse.cpp        moveMousePivot() 用的是 predict_target_position() 的返回值）

   }

---- 4. 不跳了，但瞄准点还差一点点偏上 / 偏下 -----------------------

   这是"瞄准点落在目标哪个位置"的问题，跟倍率、外推都没关系。
   悬浮窗（热键默认是 Home；键盘上没 Home 键的先照"附一"改成 F8）
   → 左侧菜单 **Aim** 分组里点 **Target** 页，往下有两个滑块：

     Approximate Head Y Offset    默认 0.05    ← 打头用这个
     Approximate Body Y Offset    默认 0.15    ← 打身子用这个

   含义：从检测框顶部往下走多少（按框高度的比例）。
   数值越大，瞄准点越往下；越小越往上。

   偏上一点点 → 往大调一档：0.05 → 0.10 → 0.15
                一边拖一边看准星，落到头正中就停手。
   偏下一点点 → 往小调。

   拖滑块当场生效：不用按 F4、不用重启；松手就自动存回 config.ini。

   拖 Head 那个滑块如果一点变化都没有（说明你的模型没在识别"头"这一类框，
   用的是整身框 + Body 偏移），那就改拖 Body 那个。

   同一个页面下面有 Preview 参考图：红线上写着 Body、绿线上写着 Head，
   画的就是这两个数值现在把瞄准点放在人体的哪个高度，可以对着调。

   两头都拖到头（0.00 或 1.00）还差一点点 → 那就不是这个的问题了，
   做第 7 步的回报，把 [Games] 那几行发我。


---- 5. 不蹦了之后：把倍率提上来 ------------------------------------

   之前被迫用 0.05，很大原因就是这个抖 —— 倍率一大，抖动被放大成"跳"。
   现在一档一档往上提：

       0.05 → 0.1 → 0.2 → 0.3

   每档进游戏试：

   · 贴上去稳、不甩         → 再往上提一档，直到刚要冲过头就退回来
   · 慢慢爬、贴不上、跟不上移动的目标 → 太小了，往上提
   · 某一档又开始"很快地左右跳"       → 退回低一档先用着，做第 6 步

   改倍率的命令（两个数填一样，让倍率固定、不随远近变）：

   $p='F:\aifz\ai_5.0.3_CUDA\config.ini'; (Get-Content $p) -replace '^\s*minSpeedMultiplier\s*=.*','minSpeedMultiplier = 0.1' -replace '^\s*maxSpeedMultiplier\s*=.*','maxSpeedMultiplier = 0.1' | Set-Content $p; Get-Content $p|Select-String 'SpeedMultiplier'


---- 6. 只有"怎么调都偏一点"时，才动 [Games] ------------------------

   先别动这一步，把第 7 步的回报发我。

   SunOne 认为"1 个鼠标计数 = 游戏转多少度"，写在 config.ini 的 [Games] 里：

     UNIFIED = 1,0.022,0.022        ← 名字 = 灵敏度, yaw, pitch

   0.022 是 CS 的标定值，跟别的游戏差好几倍。它同时决定两件事：
   算"该推多少鼠标"，以及"我自己刚才的移动把画面挪了多少"的自我补偿。
   标定对不上时，补偿会多补/少补 —— 表现就是：怎么调倍率都偏一点，
   或者倍率一提就抖。真要改就是 yaw/pitch 乘几倍、倍率同时乘几倍
   （保持手感不变），具体数值我按你的游戏和 DPI 给你算，比一档档试快。

   把 [Games] 那几行发我用这条命令：

   $p='F:\aifz\ai_5.0.3_CUDA\config.ini'; Get-Content $p | Select-String '^active_game|^\[Games\]' -Context 0,6

---- 附三：好几个人同框时，老是换目标 -------------------------------

   能不能固定打一个？能。要做的不是找什么"锁定"开关，而是
   **不让别人进识别范围**。

   先说清楚它本来是怎么工作的：
   这个工具一直有锁定（Tracker），config.ini 里 tracker_enabled 默认就是
   true，而且**按住右键（瞄准键）期间锁是保持的** —— 只要锁定的人还在被
   识别到，它就不会换人。

   换人只有一个触发点，而且是写死的：
   锁定的人连续约 15 帧（60fps 下约 0.25 秒）完全没被识别到 → 锁被丢掉 →
   立刻改选"离准星最近的那个人"。
   所以被打的人只要被掩体挡住、跑出识别范围、或者模型漏检超过 0.25 秒，
   就会跳到旁边那个人身上。这个帧数写在源码里（maxMissedFrames = 6，
   锁定目标再加 8），config.ini 改不了，只能绕。

   ------------------------------------------------
    办法：把识别范围缩小（推荐，能边打边调）
   ------------------------------------------------

   悬浮窗 → 左侧 **Vision** 分组 → **Capture** 页，往下看：

     Circle FOV          勾选框，默认已开
     Circle FOV size     滑块，默认 100%   ← 拖小它

   含义：只认"以准星为圆心、这个百分比为半径"的圈里的目标，检测框的
   中心落在圈外的人，直接不算数。圈越小，旁边的人越进不来。

     100%  = 现在这样，整个识别范围都算
     70% / 50% / 30%  一档一档往小拖，边打边看
     ~30%  基本只有准星正指着的那个人会被识别到

   别拖过头：拖太小会把正在打的人也筛掉（框中心也得在圈里），表现是
   "打着打着目标突然丢一下"。出现丢目标就说明拖太小了，往回加一档。

   （识别范围本身就是以准星为中心的一个正方形，边长由 Capture 页的
     Detection Resolution 决定，默认 320 像素；Circle FOV 是在这个正方形
     里面再收一次圈。所以 30% 大约是准星周围 96×96 像素的范围。）

   想看见这个圈：Visuals 分组 → **Game Render** 页把 `Enable` 勾上，
   再到 **Render Style** 页，Capture Frame 那一块里把 `Draw Circle Guide`
   勾上，游戏里就会画出这个圈，对着圈调最方便。

   ------------------------------------------------
    两个配套注意点
   ------------------------------------------------

   · **要一直按住右键。** 松开右键时每一帧都重新挑"离准星最近的"，
     松手再按就会换人。不想一直按 → Aim 分组 → **Target** 页，
     把 `Auto Aim` 勾上（等于一直按着）。
   · **别**去 Aim → **Tracker** 页把 `Enable Tracker` 关掉。关掉就完全
     不锁定了，每一帧都重挑最近的人，换得比现在更勤。

   ------------------------------------------------
    不开悬浮窗就直接改（改完按 F4）
   ------------------------------------------------

---- 附四：Aim → Movement 页每个参数是什么意思 ----------------------

   悬浮窗左侧 **Aim** 分组 → **Movement** 页。从上到下一共三组
   （分组标题在界面上不显示，按控件名字认，顺序就是下面这个顺序）。

   ── 第一组：FOV ─────────────────────────────────────────

     FOV X    默认 106    游戏的水平视野角（度）
     FOV Y    默认 74     游戏的垂直视野角（度）

     这两个要填**游戏里真实的 FOV 数值**。工具拿它把"目标离准星多少个
     像素"换算成"要转多少度"，再按 Profiles 页里的灵敏度换成鼠标计数。

       填小了 → 以为每像素转的角度小 → 推得不够、追不上、贴不上
       填大了 → 推过头、容易抖

     所以"倍率怎么调都差一点点"时，先回来确认这两个是不是游戏真实值。
     106 / 74 是 CS 的常用值，别的游戏差多少要按实际填。

     ── 这两个数值怎么查 ──────────────────────────────────

     要的是**游戏真实渲染的 FOV**，不是滑块上写的那串数字。

       · 16:9 下水平和垂直是绑死的，知道一个就能算另一个：

             tan(垂直 ÷ 2) = tan(水平 ÷ 2) ÷ (画面宽 ÷ 画面高)

         106 / 74 正好是 16:9 下配对的一组，反过来算：
         tan(53°) ÷ 1.7778 = 0.746 → 垂直 = 73.6 ≈ 74。
         所以填完可以拿这条公式自检，两个数不自洽就至少填错了一个。

       · 游戏设置里的 FOV 滑块有三种口径，别混：
         16:9 水平 / 4:3 基准的水平 / 垂直。
         例：CS 滑块上写 90，那是 4:3 基准的，16:9 下真实渲染值就是
         水平 106 / 垂直 74 —— 也就是工具默认的那一对。
         拿不准口径就把游戏名告诉我，我查给你。

       · 游戏自己的配置文件（ini / json / cfg）里搜 "fov"，
         经常能搜到比滑块更准确的原始值。

       · 实在查不到：先用默认值，靠倍率调手感。但要知道填错的代价不只是
         推力大小 —— 这两个值还会被拿去做"我上一帧把画面挪了多少"的反算
         （源码 mouse/mouse.cpp 里把鼠标计数换回屏幕像素那一段），
         所以填错的时候自我补偿也跟着错，表现是"怎么调倍率都偏一点、
         倍率一提就抖"。出现这个现象就要回来查真实 FOV。

     （滑块范围是 10 ~ 120 的整数。）

   ── 第二组：Speed Multiplier ─────────────────────────────

     Min Speed Multiplier   默认 0.1   离准星远时的速度倍率（下限）
     Max Speed Multiplier   默认 0.1   已经贴近目标时的速度倍率（上限）

     就是"推多快"。**两个数填一样 = 固定倍率、不随远近变**（你现在就是
     这样）。拉开成两个不同的数 = 远处快、近处慢（近处慢是为了不过冲）。

     ⚠️ 一个看不出来的坑：程序里对 60fps 抓帧会**再乘 0.5**
        （源码里是 corr = 30 / 抓帧帧率，为了让不同帧率手感一致）。
        也就是说面板上填 0.2，在 60fps 下实际生效的是 0.1。
        觉得"数填得挺大却没劲"多半就是这个。

   ── 第三组：Target correction ────────────────────────────

     这一组只管"最后一段怎么贴上去"。

     Snap Radius           默认 1.5    （范围 0.1 ~ 5.0）
       贴到多近算"已经到了"。距离小于它时不再按曲线减速，改成用一个
       略微放大过的**固定**速度顶最后一下 —— 免得最后几个像素推得太慢、
       一直差一点点贴不上。

     Snap Boost Factor     默认 1.15   （范围 0.01 ~ 4.0）
       上面"顶最后一下"的速度 = Min Speed Multiplier × 这个数。
       1.0 = 不额外加速；调大 = 进圈后顶得更狠（贴得更死，但更容易小抖）。

     Near Radius           默认 25.0   （范围 1.0 ~ 40.0）
       多近算"近"。这个距离以内速度按曲线从慢到快；超出这个距离就直接
       按距离线性给速度（越远越快）。
       注意距离是在**检测区域**里量的（一个 320 像素见方的框），
       所以 25 是那个框里的 25 像素，不是屏幕上的 25 像素。

     Speed Curve Exponent  默认 3.0    （范围 0.1 ~ 10.0）
       这条曲线的形状。值越大 = 贴近时速度压得越狠（起步温柔、最后一段
       慢），拉开距离才快起来；值越小 = 越接近一条直线（起手就冲）。

   ── 这张页面对应什么毛病 ────────────────────────────────

     · 抖 / 跳                 → 不在这页，看 附三 和 Prediction 页（外推）
     · 稳定地贴不上 / 冲过头   → 先核 FOV X / FOV Y，再动 Speed Multiplier
     · 总差最后一两像素贴不上  → Snap Boost Factor 从 1.15 往上调一点（1.3 / 1.5）
     · 贴上了但一直小抖        → Snap Boost Factor 往下调，或把 Snap Radius 调小

   查当前这一页的值：

$p='F:\aifz\ai_5.0.3_CUDA\config.ini'; Get-Content $p|Select-String 'fovX|fovY|SpeedMultiplier|snapRadius|nearRadius|speedCurveExponent|snapBoostFactor'


---- 附五：Prediction 页微调 —— 想自己试"更平滑、不抖" ---------------

   位置：悬浮窗左侧 **Aim** 分组 → **Prediction** 页（图标是条曲线）。

   这页分两段：上面是"往前猜多远"（Prediction），下面是卡尔曼滤波。
   两个是配合关系 ——
     · 外推：往前猜 → 猜准了更跟手，猜错了就是"一帧左一帧右跳"
     · 卡尔曼：只把位置本身抹平，不往前猜

   ── 先确认：往前猜现在是关着的 ──────────────────────────

     Prediction Interval                0.00     ← 归零
     Kalman Compensate Inference Delay   不勾     ← false
     Kalman Additional Predict (ms)       0.0    ← 归零

     界面会显示一行红字 `Prediction is disabled.` —— 这是正常的，就是关了。
     看现在的值：

$p='F:\aifz\ai_5.0.3_CUDA\config.ini'; Get-Content $p|Select-String 'predictionInterval|kalman_enabled|kalman_compensate_detection_delay|kalman_additional|kalman_measurement_noise|kalman_velocity_damping|kalman_process_noise'

   ── 想更平滑：把卡尔曼打开（只平滑、不往前猜）──────────

     勾上 `Enable Kalman Filter`。

     注意一件事：**卡尔曼关着的时候，程序用的是原始检测框位置，
     一点平滑都没有**（源码里那个分支直接把 position 设成测量值）。
     所以"关掉卡尔曼"有时候反而更抖。开着它 + 外推为 0 = 只滤波不预测。

     想更平滑（代价：跟手变慢，打移动目标会有点拖）：
       Kalman Measurement Noise    默认 35     往大调：80 → 150 → 300
       Kalman Process Noise Pos    默认 40     往小调：20 → 10 → 5
       Kalman Velocity Damping     默认 0.08   往大调：0.2 → 0.4 → 0.8
     觉得太肉、跟不上人，就往反方向调回去。
     一次只动一个，动完打一会儿，再动下一个。

     这几个一般不用碰：
       Kalman Process Noise Vel    默认 1800    速度响应快慢
       Kalman Max Velocity         默认 20000   速度上限
       Kalman Warmup Frames        默认 2       刚锁上目标头几帧不做速度估计；
                                                刚换目标时有个小跳就加到 3~5
       Kalman Reset Timeout (s)    默认 0.5     多久没目标就重置滤波器

   ── 想再补一点"跟手" ───────────────────────────────────

     卡尔曼开着的情况下，可以把 Prediction Interval 从 0.00 抬一点点：
     0.00 → 0.01 → 0.02，再往上就开始飘了。

     ⚠️ 顺序不能反：这个"往前猜"只有**卡尔曼开着**时才是安全的，
        因为速度是滤波过的。卡尔曼关着的时候往前猜，用的就是原始
        逐帧抖动 —— 那就是你之前遇到的"一帧往左一帧往右、跳得飞快"。
        要记牢：**先开卡尔曼，再抬 Prediction Interval**。

   ── 还是有小抖 ─────────────────────────────────────────

     那就不是滤波的问题了，是"最后贴上去那一段"，回 Movement 页（附四）：

       Snap Boost Factor   默认 1.15 → 往下调 1.0 / 0.9
       Snap Radius         默认 1.5  → 往下调 1.0 / 0.5

   ── 一句话总结这页怎么用 ───────────────────────────────

     抖 = 往前猜（三个值必须保持 0 / false / 0）
     小抖抹不平 = 开卡尔曼，加大 Measurement Noise、加大 Velocity Damping
     想跟手一点 = 卡尔曼开着的前提下，Prediction Interval 抬到 0.01~0.02
